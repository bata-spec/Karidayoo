# Karidayoo コンセプト設計書

## 1. 目的

ゲーム・小説などの創作物における「設定・資料」(キャラクター、時代背景、国、組織、伏線、用語など)を一元管理する創作支援ツール。作品ごとにデータを完全に独立させ、同名の設定(例:「魔王」)が別作品の設定と混ざらないようにする。

簡単な短編から、キャラクターや設定が多い大規模作品まで、同じ仕組みでスケールする。

## 2. 想定利用シーン

- 個人のクリエイター(小説家、ゲームシナリオライターなど)
- スマホ・PCの両方で編集/閲覧
- 開発環境はスマホ(Termux)のみを想定し、重いビルドはローカルで行わずGitHub Actionsに任せる

## 3. コア機能

### 3.1 作品(プロジェクト)ごとの独立管理

- 作品単位でデータを分離。作品を切り替えるとエントリ・カテゴリ・テンプレートも丸ごと切り替わる。

### 3.2 設定・資料エントリ

- エントリ = 1つの設定/資料単位(キャラクター、国、時代、組織、伏線など)
- カテゴリは固定せず、作品ごとに自由に作成できる
- 各エントリは以下を持つ:
  - タイトル
  - カテゴリ
  - タグ(自由入力の複数タグ)
  - 属性(properties):項目名と値の自由なkey-valueリスト。固定フォームではなく、ユーザーが必要な項目を都度追加する。よく使う項目セットは「テンプレート」として保存し、次回はワンタップで挿入できる
  - 本文(body):自由記述のテキスト
  - 関連(relations):他のエントリへの参照 + 関係ラベル(自由文字列。例:「敵対」「師弟」「所属」「幼馴染」)
  - 画像(images):複数枚添付可能、うち1枚を「メイン画像」に指定可能

### 3.3 自動Wikiリンク

- 本文中に他エントリのタイトルと一致する語があれば自動検出し、青文字リンクとして表示
- タップ/クリックでそのエントリの閲覧画面へジャンプ
- リンク解決は同一作品内のエントリのみが対象(作品をまたいだ誤爆を防ぐ)

### 3.4 関係性の可視化(グラフビュー)

- エントリの`relations`を元に、ノード(エントリ)とエッジ(関係ラベル付き)からなるグラフを自動描画
- レイアウトは自動計算(force-directed)。ユーザーが手動で位置決めする必要はない(ドラッグでの一時調整は可)
- 表示は2段階:
  - 全体グラフ(カテゴリ/タグでフィルタ可能)
  - 個エントリ視点のローカルグラフ(そのエントリと直接繋がる相手を中心に表示)
- ノードはカテゴリ別に色分け、メイン画像があれば丸アイコンとして表示
- ノードタップでそのエントリの編集/閲覧画面へ遷移

### 3.5 画像添付

- エントリに画像を複数枚添付可能、1枚をメイン画像として指定
- 画像を指定していれば表示し、指定していなければ何も表示しない(代替アイコン等は出さない)
- 画像ファイルが見つからない場合(同期漏れなど)はエラーではなく控えめな「見つかりません」表示にする

## 4. データモデル(ドラフト)

```json
{
  "id": "char_001",
  "workId": "work_abc",
  "category": "キャラクター",
  "title": "アルド",
  "tags": ["主人公", "騎士団"],
  "properties": [
    { "key": "年齢", "value": "17" },
    { "key": "所属", "value": "王国騎士団" }
  ],
  "body": "王国騎士団に所属する青年。幼い頃に魔王の襲撃で故郷を失い...",
  "relations": [
    { "targetId": "char_002", "label": "幼馴染" },
    { "targetId": "org_001", "label": "所属" }
  ],
  "images": [
    { "id": "img_001", "file": "images/char_001_main.jpg", "caption": "通常衣装", "isMain": true }
  ],
  "createdAt": "2026-08-20T00:00:00Z",
  "updatedAt": "2026-08-20T00:00:00Z"
}
```

ユーザーはこのJSONを直接編集することはなく、フォームUIを通じて操作する。JSONはあくまで保存/交換用の形式。

## 5. 技術スタック

- **フロントエンド**: React + TypeScript + Vite
- **モバイル配布**: Capacitorでスマホ用APKにラップ
- **ビルド**: GitHub Actionsでweb資産のビルドとAndroid APKビルドを自動化(ローカルでの重いビルド作業が不要)
- **PC利用**: そのままブラウザで動作するWebアプリとして利用

選定理由: Node.js/npmのみで開発が完結するため、Termux(スマホ)上でも開発を進めやすい。PCはブラウザでそのまま動き、スマホ用は同じコードをCapacitorでAPK化できる。

## 6. 画面構成/遷移

```
[ホーム(作品一覧)]
   │  ＋新しい作品を作る / 作品を選ぶ
   ▼
[作品ダッシュボード] ── ヘッダーに作品切替・作品設定(名前変更/JSONエクスポート/削除)
   ├─ タブ:エントリ一覧
   ├─ タブ:グラフビュー(全体)
   └─ タブ:テンプレート管理
          │
          ▼
   [エントリ一覧] → タップ → [エントリ閲覧画面] ──編集──▶ [エントリ編集画面]
                                  │ 本文の青リンク/関連チップ/グラフのノードから
                                  │ 別エントリへジャンプ(履歴で戻れる)
```

## 7. データ保存・同期

- **表示・編集用の高速キャッシュ**: ブラウザのIndexedDBに保存(サクサク動く作業用データ)
- **実体データ**: 本物のJSONファイル(+画像ファイル)として書き出す
  - PC: File System Access API対応ブラウザでは保存先フォルダを直接指定して読み書き。非対応ブラウザでは手動エクスポート/インポートで代替
  - スマホ: Capacitorのファイル機能で端末のドキュメントフォルダに保存
- **端末間同期(V1)**: 自前サーバーは持たない。保存先フォルダをGoogle Driveなどのクラウド同期フォルダに指定してもらうか、作品単位のJSONエクスポート/インポートで手動同期する
- **画像**: サイズが大きいため、保存時に自動リサイズ/圧縮してから保存する
- **既知の制約**: 複数端末でほぼ同時編集した場合の競合解決はV1では厳密に行わない(後勝ち)。将来的にリアルタイム同期が必要になれば、簡易バックエンド(Firebase/Supabaseなど)を追加する余地を残す
